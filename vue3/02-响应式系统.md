# Vue 3 响应式系统

> 响应式是 Vue 的心脏。理解它，才算真正入门 Vue。本文从使用到原理，从场景到源码。

---

## 一、什么是响应式

### 1.1 一句话

**数据变 → 视图自动变，不需要手动操作 DOM。**

```js
// ❌ jQuery 时代 —— 手动更新 DOM
$('#count').text(count)

// ✅ Vue 响应式 —— 数据变了，视图自动跟
const count = ref(0)
count.value++  // 视图自动 +1
```

---

### 1.2 本质

Vue 的公式：

> **UI = render(state)**

响应式系统负责：**当 `state` 变化时，自动重新执行 `render`**。

```
数据变化 → 通知依赖这个数据的地方 → 自动重新渲染
```

---

### 1.3 Vue 2 vs Vue 3 响应式原理对比

| | Vue 2 | Vue 3 |
|------|------|------|
| 底层技术 | `Object.defineProperty` | `Proxy` |
| 能检测对象属性增删 | ❌ | ✅ |
| 能检测数组索引修改 | ❌ | ✅ |
| 能检测数组 length 变化 | ❌ | ✅ |
| 初始化时遍历所有属性 | ✅（递归） | ❌（惰性，用到才代理） |
| 需要额外 API | `Vue.set()` / `Vue.delete()` | 不需要 |
| 对 Map / Set / WeakMap 等 | ❌ 不支持 | ✅ 支持 |

## 二、ref — 响应式数据的基础

### 2.1 基本用法

```vue
<script setup>
import { ref } from 'vue'

const count = ref(0)
const name = ref('Alice')
const obj = ref({ a: 1 })

console.log(count.value)   // 0 —— JS 中访问需要 .value
count.value++              // 修改也需要 .value
</script>

<template>
  <!-- 模板中会自动解包，不需要 .value -->
  <p>{{ count }}</p>
  <button @click="count++">+1</button>
</template>
```

---

### 2.2 为什么需要 `.value`

`ref` 的本质是包装了一个对象：

```js
// 简化版 ref 实现
class RefImpl {
  constructor(value) {
    this._value = value
    this.__v_isRef = true  // 标记，供自动解包使用
  }
  get value() {
    track(this, 'value')    // 依赖收集
    return this._value
  }
  set value(newVal) {
    if (newVal !== this._value) {
      this._value = newVal
      trigger(this, 'value')  // 触发更新
    }
  }
}
```

因为基本类型（number、string）是值传递，无法被 Proxy 拦截，所以需要包一层对象，通过 `.value` 的 getter/setter 来拦截。

---

### 2.3 模板自动解包

```vue
<script setup>
const count = ref(0)
const obj = { nested: ref(1) }
</script>

<template>
  <!-- ✅ 顶层 ref 自动解包 -->
  <p>{{ count }}</p>   <!-- 不需要 .value -->

  <!-- ❌ 嵌套在对象里的 ref 不会自动解包 -->
  <p>{{ obj.nested }}</p>     <!-- 这会显示 { "value": 1 } ？不，Vue 3.3+ 模板也支持解包了 -->
  <p>{{ obj.nested.value }}</p>  <!-- 但为了可读性，还是推荐明确写 -->
</template>
```

**自动解包只在以下情况生效**：
1. 顶层 `ref`（`setup` 返回的，或 `<script setup>` 声明的）
2. `reactive` 对象内部嵌套的 `ref`（见下文）

---

### 2.4 ref 可以包装任何值

```js
const num = ref(0)           // 基本类型
const str = ref('hello')     // 字符串
const obj = ref({ count: 0 }) // 对象 —— 内部会用 reactive 处理
const arr = ref([1, 2, 3])   // 数组
```

**注意**：当 `ref()` 传入对象时，内部会自动调用 `toReactive(value)` 把值转成 `reactive`：

```js
// Vue 源码中 ref 的 setter 简化逻辑
set value(newVal) {
  this._value = toReactive(newVal)
  // toReactive: 如果是对象 → reactive(val)；如果是基本类型 → 原样返回
}
```

所以：

```js
const obj = ref({ count: 0 })
obj.value.count = 1  // ✅ 响应式！因为内部被 reactive 代理了
```

## 三、reactive — 对象的响应式

### 3.1 基本用法

```vue
<script setup>
import { reactive } from 'vue'

const state = reactive({
  count: 0,
  user: {
    name: 'Alice',
    age: 25,
  },
  items: [1, 2, 3],
})

// 访问和修改都不需要 .value
state.count++
state.user.name = 'Bob'
state.items.push(4)
</script>

<template>
  <p>{{ state.count }}</p>
  <p>{{ state.user.name }}</p>
</template>
```

---

### 3.2 reactive 的限制

| 限制 | 说明 |
|------|------|
| **只能包装对象类型** | 不能 `reactive(0)`、`reactive('hello')` |
| **不能替换整个对象** | `state = reactive({...})` 会丢失响应式 |
| **解构会丢失响应式** | `let { count } = state` 后 `count` 不再是响应式 |
| **不能直接赋值给 ref** | `const r = reactive({ a: 1 })` 再把 `r` 赋值给别的变量就断了代理链路 |

---

### 3.3 解构问题与解决

```vue
<script setup>
import { reactive, toRefs } from 'vue'

const state = reactive({ count: 0, name: 'Alice' })

// ❌ 丢失响应式
const { count, name } = state
// count 现在只是一个普通数字 0

// ✅ toRefs：转为 ref 引用，保持响应式
const { count: countRef, name: nameRef } = toRefs(state)
countRef.value++  // state.count 同步变化！
</script>

<template>
  <!-- 可以直接使用 ref（自动解包） -->
  <p>{{ countRef }}</p>
</template>
```

`toRefs` 做了什么事？

```js
// 简化理解
function toRefs(obj) {
  const result = {}
  for (const key in obj) {
    result[key] = toRef(obj, key)
  }
  return result
}
// toRef 创建一个与源对象链接的 ref
// 修改 ref.value 会影响源对象，反之亦然
```

## 四、ref vs reactive 全方位对比

| | ref | reactive |
|------|------|------|
| 参数类型 | 任意（基本类型、对象） | 仅对象/数组/Map/Set |
| 访问方式 | `.value` | 直接访问 |
| 模板中 | 自动解包（顶层） | 直接使用 |
| 解构 | 保持响应式 ✅ | 丢失响应式 ❌ |
| 替换整个值 | `ref.value = newVal` ✅ | `state = {...}` ❌ |
| 内部实现 | `RefImpl` 类 | `Proxy` |
| 传给函数 | 传的是包装后的对象 | 传的是 Proxy 对象 |
| TypeScript | 需要 `.value`，可能啰嗦 | 自然 |
| 官方推荐 | 通用，可逐级采用 | 适合表单状态等对象聚合场景 |

---

### 使用建议

```
┌─────────────────────────────────┐
│  存放基本类型（字符串、数字等）    │  → ref
│  存放可能被整个替换的数据          │  → ref
│  存放从 API 获取的数据            │  → ref
│  表单状态（聚合多个字段）          │  → reactive + toRefs
│  不想写 .value                   │  → reactive（但要接受限制）
│  组合式函数返回值                 │  → ref（可逐个解构）
└─────────────────────────────────┘
```

实际上，Vue 社区正在向 **"默认都用 ref"** 的方向发展，因为 `ref` 更加灵活且没有解构丢失响应式的坑。

## 五、ref 自动解包的深层规则

### 5.1 reactive 包裹 ref

```js
const count = ref(0)
const state = reactive({ count })

state.count  // 0 —— 自动解包，不需要 .value
state.count = 5  // ✅ 同时更新 count.value

// 对 ref 赋值会替换掉整个 ref
state.count = ref(10)  // count 现在指向新的 ref
```

---

### 5.2 数组/集合中的 ref 不会自动解包

```js
const list = reactive([ref(0), ref(1)])

list[0]      // { value: 0 } —— 没有自动解包！
list[0].value // 0 —— 必须手动 .value
```

---

### 5.3 模板中 ref 解包的情况

```vue
<script setup>
const count = ref(0)

// template 中：
// ✅ count → 自动解包
// ✅ obj.count（obj 是 reactive 时）→ 自动解包
// ❌ arr[0]（arr 是 reactive 且元素是 ref）→ 不解包
</script>
```

## 六、相关工具 API

### 6.1 toRef / toRefs

```js
import { reactive, toRef, toRefs } from 'vue'

const state = reactive({ count: 0, name: 'Alice' })

// toRef：给单个属性建响应式引用
const countRef = toRef(state, 'count')
countRef.value++  // state.count 也变成 1

// toRefs：一次性全部转换
const { count, name } = toRefs(state)
// count 和 name 都是 Ref 类型，且与 state 保持链接
```

**使用场景**：把 reactive 对象的属性传给 composable 函数时保持响应式。

---

### 6.2 unref — 统一取值

```js
import { unref } from 'vue'

// unref(val) = val.value（如果 val 是 ref）；否则原值
const count = ref(0)
unref(count)  // 0 —— 等价于 isRef(val) ? val.value : val
unref(5)      // 5

// 在 composable 中极为常用
function useSomething(param) {
  const val = unref(param)  // 不管传入 ref 还是普通值，都能正确取值
}
```

---

### 6.3 isRef / isReactive / isProxy / isReadonly

```js
import { isRef, isReactive, isProxy, isReadonly } from 'vue'

const r = ref(0)
const o = reactive({})
const ro = readonly({})

isRef(r)       // true
isReactive(o)  // true
isProxy(o)     // true（reactive 返回的是 Proxy）
isProxy(ro)    // true
isReadonly(ro) // true
```

---

### 6.4 shallowRef / shallowReactive

```js
import { shallowRef } from 'vue'

// 普通 ref：深层对象也会被代理
const deep = ref({ nested: { count: 0 } })
deep.value.nested.count++  // ✅ 响应式

// shallowRef：只有 .value 的替换是响应式的
const shallow = shallowRef({ nested: { count: 0 } })
shallow.value.nested.count++  // ❌ 不触发更新
shallow.value = { nested: { count: 1 } }  // ✅ 替换整个对象触发更新
```

**使用场景**：
- 大数据量可视化（图表数据整体替换）
- 与第三方非响应式库集成（保留原始对象引用）
- 不可变数据模式

---

### 6.5 readonly

```js
import { readonly } from 'vue'

const original = reactive({ count: 0 })
const copy = readonly(original)

original.count++  // ✅ 触发更新
copy.count++      // ❌ 报错！只读

// copy 随 original 变化
original.count = 5
console.log(copy.count)  // 5
```

---

### 6.6 toRaw / markRaw

```js
import { toRaw, markRaw, reactive } from 'vue'

const obj = { count: 0 }
const state = reactive(obj)

toRaw(state) === obj    // true —— 拿到原始对象

const raw = markRaw({ count: 0 })
const state2 = reactive({ raw })
state2.raw.count++  // raw 是原始对象，不会被代理，不触发更新
```

`markRaw` 使用场景：第三方类实例、DOM 引用、复杂不可变数据结构。

## 七、原理：依赖收集与触发更新

### 7.1 三个核心角色

```
effect（副作用）  ──▶   track（收集依赖）  ──▶  targetMap（依赖仓库）
                                                      │
                      trigger（触发更新）  ◀───────────┘
```

---

### 7.2 大白话解释

```
1. 有一个仓库（targetMap），存着「哪个对象的哪个属性，被谁依赖了」

2. 当代码读取 state.count 时（get）
   └── track()：把当前的 effect 记录下来
   └── "record: state.count 被 effect-1 依赖"

3. 当代码修改 state.count 时（set）
   └── trigger()：找到所有依赖 state.count 的 effect
   └── 逐个执行
```

---

### 7.3 简化版实现

```js
// 全局：当前正在执行的 effect
let activeEffect = null

// 仓库结构：targetMap = WeakMap<target, Map<key, Set<effect>>>
const targetMap = new WeakMap()

// 收集依赖
function track(target, key) {
  if (!activeEffect) return
  let depsMap = targetMap.get(target)
  if (!depsMap) {
    targetMap.set(target, (depsMap = new Map()))
  }
  let deps = depsMap.get(key)
  if (!deps) {
    depsMap.set(key, (deps = new Set()))
  }
  deps.add(activeEffect)
}

// 触发更新
function trigger(target, key) {
  const depsMap = targetMap.get(target)
  if (!depsMap) return
  const deps = depsMap.get(key)
  if (deps) {
    deps.forEach(effect => effect())
  }
}

// Proxy 实现 reactive
function reactive(target) {
  return new Proxy(target, {
    get(target, key, receiver) {
      const result = Reflect.get(target, key, receiver)
      track(target, key)                    // ← 依赖收集
      return result
    },
    set(target, key, value, receiver) {
      const oldValue = target[key]
      const result = Reflect.set(target, key, value, receiver)
      if (oldValue !== value) {
        trigger(target, key)                // ← 触发更新
      }
      return result
    }
  })
}
```

---

### 7.4 惰性代理（关键优化）

Vue 3 只在访问到嵌套对象时才创建 Proxy：

```js
const state = reactive({
  a: {           // 这个嵌套对象在被读取时才会被 reactive
    b: {
      c: 1       // 同理，访问到 .b 才会 reactive
    }
  }
})

// 如果从来没访问 state.a.b，那么 b 永远不会被 Proxy 包裹
// 这对比 Vue 2 递归遍历所有属性是巨大的性能提升
```

## 八、面试重点梳理

### 8.1 Vue 2 vs Vue 3 响应式原理

> Vue 2 用 `Object.defineProperty` 逐个劫持已有属性，**无法检测属性增删和数组索引修改**，需要 `Vue.set`/`Vue.delete`。
> Vue 3 用 `Proxy` 代理整个对象，支持属性增删、数组索引修改，且惰性代理嵌套对象，性能更好。

---

### 8.2 ref 和 reactive 的区别

> - `ref` 通过 getter/setter 拦截 `.value`，可包装任意类型；`reactive` 通过 `Proxy` 代理，只能包装对象
> - `ref` 解构后保持响应式，`reactive` 解构后丢失
> - `ref` 在模板中自动解包（顶层），`reactive` 直接使用
> - `ref` 可以整体替换，`reactive` 不能

---

### 8.3 为什么 ref 需要 .value

> 基本类型是值传递，无法被 Proxy。因此需要包装成对象，通过 getter/setter 拦截 `.value` 的读写来实现依赖收集和触发更新。

---

### 8.4 reactive 传递对象引用时丢失响应式？

> 不会。`reactive` 返回的是 Proxy 代理对象，只要传递的是同一个 Proxy，就不会丢失响应式。但如果用 `toRaw` 获取原始对象，或解构到普通变量，就会丢失。

---

### 8.5 Proxy 相比 defineProperty 的优势

```
1. 能检测属性增删（deleteProperty 陷阱）
2. 能检测数组索引修改和 length 变化
3. 惰性代理：不需要在初始化时递归遍历所有属性
4. 支持 Map、Set、WeakMap、WeakSet
5. 性能更好：代理整个对象，而非逐个属性劫持
```

## 九、常见坑点

### 9.1 ref 的 .value 和 JSON

```js
const obj = ref({ a: 1 })
console.log(JSON.stringify(obj))  // {"_value":{"a":1},"__v_isRef":true}
// ❌ 不是预期的 {"a":1}！
// 这是因为 ref 的本质是一个对象
console.log(JSON.stringify(obj.value))  // {"a":1} ✅
```

---

### 9.2 不要用解构 reactive 的 props

```js
const state = reactive({ count: 0 })

// ❌ count 现在只是一个普通数字，不再响应
let { count } = state

// ✅ 用 toRefs
let { count } = toRefs(state)
```

---

### 9.3 watch 监听 ref 时注意

```js
const count = ref(0)
const obj = ref({ a: 1 })

// ✅ watch 会自动解包 ref
watch(count, (newVal) => console.log(newVal))
// newVal 是 0, 1, 2... 不是 { value: 0 }

// ⚠️ 但 ref 包装对象时，默认不深度监听
watch(obj, () => console.log('changed'))
obj.value.a = 2  // ❌ 不会触发（需要 { deep: true }）
```

---

### 9.4 大数组/深对象的性能优化

```js
// ❌ 不必要的深层响应式
const hugeList = ref([...百万条数据])  // 深层代理，昂贵

// ✅ 只对引用替换保持响应式
const hugeList = shallowRef([...百万条数据])
hugeList.value = newData  // 整体替换才触发更新
```

## 十、总结

```
ref        → 一切都可以 ref，解构安全，template 自动解包
reactive   → 只用于对象，无 .value，解构易失响应
shallowRef → 浅层响应，大数据整体替换场景
toRefs     → reactive 对象的解构救星
readonly   → 保护数据不被修改
markRaw    → 标记不代理，第三方实例专用

原理核心：get 时 track()，set 时 trigger()
```
