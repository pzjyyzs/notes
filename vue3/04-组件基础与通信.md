# Vue 3 组件基础与通信

> 组件是 Vue 的核心抽象。组件通信是日常开发中最频繁的操作。本文覆盖从入门定义到高级通信模式。

---

## 一、组件是什么

### 1.1 一句话

**组件 = 独立的、可复用的 UI 片段，拥有自己的模板、逻辑和样式。**

```
应用
 └─ 布局组件 (Layout)
      ├─ 头部组件 (Header)
      │    ├─ 导航组件 (Nav)
      │    └─ 搜索栏组件 (SearchBar)
      ├─ 内容区 (Main)
      │    ├─ 列表组件 (List)
      │    │    └─ 列表项组件 (ListItem) × N
      │    └─ 侧边栏组件 (Sidebar)
      └─ 底部组件 (Footer)
```

---

### 1.2 组件定义的三种方式

```vue
<!-- ① 单文件组件 SFC（最常用） -->
<script setup>
import { ref } from 'vue'
const count = ref(0)
</script>

<template>
  <button @click="count++">{{ count }}</button>
</template>

<style scoped>
button { color: blue; }
</style>
```

```js
// ② Options API 对象
export default {
  data() {
    return { count: 0 }
  },
  template: `<button @click="count++">{{ count }}</button>`
}
```

```js
// ③ 纯 JS 函数组件（无状态，极简场景）
const Hello = (props, { slots, emit, attrs }) => {
  return h('p', null, `Hello ${props.name}`)
}
```

## 二、组件注册

### 2.1 全局注册

```js
// main.js
import { createApp } from 'vue'
import App from './App.vue'
import BaseButton from './components/BaseButton.vue'

const app = createApp(App)
app.component('BaseButton', BaseButton)  // 全局可用
app.mount('#app')
```

**缺点**：即使不使用，也会被打包进去（tree-shaking 无法移除）。

---

### 2.2 局部注册（推荐）

```vue
<script setup>
import BaseButton from './components/BaseButton.vue'
// 导入后直接使用，无需注册
</script>

<template>
  <BaseButton>点击</BaseButton>
</template>
```

`<script setup>` 中导入的组件自动完成局部注册。

## 三、Props — 父传子

### 3.1 基本用法

```vue
<!-- 父组件 -->
<template>
  <UserCard :name="userName" :age="25" :is-admin="true" />
</template>

<!-- 子组件 UserCard.vue -->
<script setup>
// ① 简单声明
const props = defineProps(['name', 'age', 'isAdmin'])

// ② 带类型声明（推荐）
const props = defineProps({
  name: String,
  age: { type: Number, required: true },
  isAdmin: { type: Boolean, default: false },
})

// ③ TypeScript 类型声明
const props = defineProps<{
  name: string
  age: number
  isAdmin?: boolean
}>()

// ④ TypeScript + 默认值
const props = withDefaults(defineProps<{
  name?: string
  age: number
}>(), {
  name: '匿名用户',
})
</script>

<template>
  <p>{{ props.name }} - {{ props.age }}</p>
</template>
```

---

### 3.2 Props 单向数据流

```
父组件的 data → props → 子组件

子组件不能直接修改 props
试图修改会触发 Vue 警告
```

```vue
<script setup>
const props = defineProps({ count: Number })

// ❌ 不要直接改 props
// props.count++  // 警告：Attempting to mutate prop

// ✅ 如果确实需要改，在子组件内部复制一份
import { ref } from 'vue'
const localCount = ref(props.count)  // 创建本地副本
</script>
```

---

### 3.3 Prop 校验

```js
defineProps({
  status: {
    type: String,
    required: true,
    validator: (value) => {
      return ['active', 'inactive', 'pending'].includes(value)
    }
  },
  // 自定义验证：传了 id 或 uid 之一即可
  id: String,
  uid: String,
  validator: (props) => {
    return props.id || props.uid
  }
})
```

---

### 3.4 Boolean 类型的特殊转换

```vue
<!-- 只写属性名，不写值 = 传 true -->
<MyComponent disabled />
<!-- 等价于 :disabled="true" -->
```

```js
// 如果声明了 Boolean 类型
defineProps({ disabled: Boolean })

// 没有传 disabled → props.disabled === false
// 传了 disabled（无值）→ props.disabled === true
```

## 四、Emits — 子传父

### 4.1 基本用法

```vue
<!-- 子组件 -->
<script setup>
// ① 简单声明
const emit = defineEmits(['update', 'delete'])

// ② TypeScript 声明（推荐）
const emit = defineEmits<{
  update: [id: number, name: string]     // (e: 'update', id: number, name: string)
  delete: [id: number]                    // (e: 'delete', id: number)
}>()

function handleClick() {
  emit('update', 1, 'Alice')
}
</script>

<template>
  <button @click="handleClick">更新</button>
  <button @click="emit('delete', 1)">删除</button>
</template>

<!-- 父组件 -->
<template>
  <ChildComponent
    @update="handleUpdate"
    @delete="handleDelete"
  />
</template>

<script setup>
function handleUpdate(id, name) {
  console.log(`更新 id=${id}，名称=${name}`)
}
function handleDelete(id) {
  console.log(`删除 id=${id}`)
}
</script>
```

---

### 4.2 事件校验（Vue 3.4+）

```js
const emit = defineEmits({
  // 返回 true 有效，false 无效（仍会触发，但控制台警告）
  submit: ({ email, password }) => {
    return email && password
  }
})
```

## 五、v-model 组件通信（双向绑定）

### 5.1 回顾 v-model 本质

```vue
<input v-model="text" />
<!-- 等价于 -->
<input :value="text" @input="text = $event.target.value" />
```

### 5.2 组件上的 v-model

```vue
<!-- 父组件 -->
<MyInput v-model="text" />
<!-- 等价于 -->
<MyInput :modelValue="text" @update:modelValue="newVal => text = newVal" />
```

```vue
<!-- 子组件 MyInput.vue -->
<script setup>
const props = defineProps(['modelValue'])
const emit = defineEmits(['update:modelValue'])
</script>

<template>
  <input
    :value="modelValue"
    @input="emit('update:modelValue', $event.target.value)"
  />
</template>
```

---

### 5.3 命名 v-model

```vue
<!-- 父组件：一个组件可以绑定多个 v-model -->
<UserForm
  v-model:name="userName"
  v-model:email="userEmail"
/>

<!-- 子组件 -->
<script setup>
const props = defineProps(['name', 'email'])
const emit = defineEmits(['update:name', 'update:email'])
</script>

<template>
  <input :value="name" @input="emit('update:name', $event.target.value)" />
  <input :value="email" @input="emit('update:email', $event.target.value)" />
</template>
```

---

### 5.4 v-model 修饰符

```vue
<!-- 父组件 -->
<MyInput v-model.capitalize="text" />

<!-- 子组件 MyInput.vue -->
<script setup>
const props = defineProps({
  modelValue: String,
  modelModifiers: { default: () => ({}) }
})
const emit = defineEmits(['update:modelValue'])

function emitValue(e) {
  let value = e.target.value
  if (props.modelModifiers.capitalize) {
    value = value.charAt(0).toUpperCase() + value.slice(1)
  }
  emit('update:modelValue', value)
}
</script>
```

---

### 5.5 defineModel（Vue 3.4+ 新语法）

```vue
<!-- 子组件：更简洁的写法 -->
<script setup>
// 替代 defineProps + defineEmits
const model = defineModel()           // 默认 modelValue
// 或
const name = defineModel('name')      // 命名
// 带默认值
const count = defineModel('count', { default: 0 })
// 修饰符
const [model, modifiers] = defineModel()
</script>

<template>
  <!-- 直接读写，像 ref 一样用 -->
  <input v-model="model" />
</template>
```

## 六、provide / inject — 跨层级通信

### 6.1 为什么需要

```
props 逐层传递的问题（Prop Drilling）：

  App（有数据）
   └─ 中间组件
       └─ 中层组件
           └─ 目标组件（最终需要数据）

中间每一层都要声明 props 并向下传递，即使自己不需要。
```

---

### 6.2 基本用法

```vue
<!-- 祖先组件 -->
<script setup>
import { provide, ref } from 'vue'

const theme = ref('dark')
const updateTheme = (val) => { theme.value = val }

// provide(key, value)
provide('theme', theme)
provide('updateTheme', updateTheme)
</script>

<!-- 后代组件（可以是任意深度的后代） -->
<script setup>
import { inject } from 'vue'

const theme = inject('theme')              // 'dark'
const updateTheme = inject('updateTheme')  // 函数

// 带默认值
const size = inject('size', 'medium')
// 带工厂函数默认值
const config = inject('config', () => ({ debug: false }))
</script>
```

---

### 6.3 响应式 provide

```js
// 祖先
import { provide, ref, readonly } from 'vue'

const user = ref({ name: 'Alice', role: 'admin' })
provide('user', readonly(user))  // 用 readonly 保护，不让子孙随意修改

const updateUser = (newUser) => { user.value = newUser }
provide('updateUser', updateUser)  // 暴露修改方法
```

> **最佳实践**：数据用 `readonly` 包裹提供，修改方法单独 provide，保证数据流可控。

---

### 6.4 用 Symbol 做 key（避免命名冲突）

```js
// keys.js
export const USER_KEY = Symbol('user')
export const THEME_KEY = Symbol('theme')

// 祖先
import { USER_KEY } from './keys'
provide(USER_KEY, user)

// 后代
import { USER_KEY } from './keys'
const user = inject(USER_KEY)
```

---

### 6.5 provide / inject vs props / emits

| | props + emits | provide + inject |
|------|:---:|:---:|
| 通信方向 | 父 ↔ 子（直接） | 祖先 → 后代（任意层级） |
| 数据流清晰度 | ✅ 显式声明，一目了然 | ⚠️ 隐式，需查看 provide 才能追踪 |
| 适用场景 | 父子直接通信 | 跨多层级的全局状态（主题、语言、用户信息） |
| 响应式 | ✅ | ✅（需传 ref/reactive） |
| 类型安全 | ✅（TypeScript 原生支持） | ⚠️ 需额外处理 |

## 七、Attrs — 透传属性

### 7.1 什么是透传

```vue
<!-- 父组件 -->
<MyButton class="large" id="btn" @click="handleClick" />

<!-- MyButton.vue -->
<template>
  <button>点击</button>
</template>
```

**渲染结果**：

```html
<button class="large" id="btn">点击</button>
```

`class`、`id`、`@click` 等会**自动透传**到子组件的根元素上。

---

### 7.2 useAttrs 获取所有透传属性

```vue
<script setup>
import { useAttrs } from 'vue'

const attrs = useAttrs()
console.log(attrs)  // { class: 'large', id: 'btn', onClick: fn }
</script>

<template>
  <!-- 手动指定哪个元素接收透传 -->
  <div>
    <button v-bind="attrs">实际接收透传的元素</button>
  </div>
</template>

<script>
// 禁用自动透传
export default { inheritAttrs: false }
</script>
```

## 八、组件暴露与模板引用

### 8.1 defineExpose — 暴露方法和数据

```vue
<!-- 子组件 -->
<script setup>
import { ref } from 'vue'

const count = ref(0)
const reset = () => { count.value = 0 }

// 显式暴露：父组件只能访问暴露的内容
defineExpose({ count, reset })
</script>

<!-- 父组件 -->
<script setup>
import { ref, onMounted } from 'vue'

const childRef = ref(null)

onMounted(() => {
  console.log(childRef.value.count)   // 0
  childRef.value.reset()              // 调用子组件方法
})
</script>

<template>
  <ChildComponent ref="childRef" />
</template>
```

> **注意**：`<script setup>` 中的变量默认是私有的，必须通过 `defineExpose` 才能被父组件访问。

## 九、组件通信全景图

```
                        父组件
                          │
              ┌───────────┼───────────┐
              │ props     │           │
              ▼           │ provides  │
           子组件1        │           │
              │           ▼           │
              │ emits  任何后代组件    │
              │           │           │
              │       祖先组件         │
              │           │           │
              │        inject ▲       │
              │           │           │
              └───────────┘           │
                          └───────────┘
```

| 方式 | 方向 | 适用场景 |
|------|:---:|------|
| `props` | 父 → 子 | 直接父子关系 |
| `emits` | 子 → 父 | 子组件通知父组件 |
| `v-model` | 双向 | 表单类组件 |
| `provide/inject` | 祖先 → 后代 | 跨多层，全局配置 |
| `ref + defineExpose` | 父 → 子（方法） | 父组件需要调用子组件方法 |
| `useAttrs` | 父 → 子（透传） | 封装原生元素或第三方组件 |
| **状态管理（Pinia）** | 全局 | 复杂跨组件共享状态 |

## 十、实战：完整用户表单组件

```vue
<!-- 父组件 Parent.vue -->
<script setup>
import { ref } from 'vue'
import UserForm from './UserForm.vue'

const user = ref({ name: '', email: '', role: 'user' })
</script>

<template>
  <UserForm
    v-model:name="user.name"
    v-model:email="user.email"
    :role="user.role"
    @submit="handleSubmit"
  />
</template>

<!-- 子组件 UserForm.vue -->
<script setup>
const props = defineProps({
  role: { type: String, default: 'user' },
})
const emit = defineEmits(['submit'])

// defineModel 是 Vue 3.4 新语法
const name = defineModel('name')
const email = defineModel('email', { default: '' })

// 本地状态
const errors = ref({})

function validate() {
  errors.value = {}
  if (!name.value) errors.value.name = '请输入姓名'
  if (!email.value) errors.value.email = '请输入邮箱'
  return Object.keys(errors.value).length === 0
}

function handleSubmit() {
  if (validate()) {
    emit('submit', { name: name.value, email: email.value, role: props.role })
  }
}
</script>

<template>
  <form @submit.prevent="handleSubmit">
    <div>
      <label>姓名：</label>
      <input v-model="name" />
      <span v-if="errors.name">{{ errors.name }}</span>
    </div>
    <div>
      <label>邮箱：</label>
      <input v-model="email" />
      <span v-if="errors.email">{{ errors.email }}</span>
    </div>
    <div>角色：{{ role }}</div>
    <button type="submit">提交</button>
  </form>
</template>
```

## 十一、面试高频题

### 1. Vue 组件间有哪些通信方式？

> 1. **props + emits**：父子直接通信
> 2. **v-model**：语法糖，`:modelValue` + `@update:modelValue`
> 3. **provide / inject**：跨层级注入（主题、国际化）
> 4. **ref + defineExpose**：父组件获取子组件实例
> 5. **useAttrs**：透传未声明的 props 和事件
> 6. **Pinia / Vuex**：全局状态管理
> 7. **事件总线**（Vue 3 不推荐，可用 mitt）

---

### 2. props 为什么是单向的？

> 父组件状态变化时，新的 prop 值会重新传入并覆盖子组件的值。如果子组件也能修改 prop，会造成数据流混乱——父组件和子组件各自持有不同的值，无法确定真正的数据来源。这是 Vue 遵循「单向数据流」原则的体现。

---

### 3. defineProps 和 defineEmits 为什么不需要 import？

> 它们是**编译器宏**，在 `<script setup>` 编译阶段会被 Vue 的编译器识别并转换为对应的代码。编译后它们不存在于运行时代码中，所以不需要导入。

---

### 4. provide / inject 是响应式的吗？

> 默认情况下，**不是**。如果 provide 一个普通值（如字符串），后代 inject 后拿到的只是那个时刻的快照。要实现响应式，需要 provide 一个 `ref` 或 `reactive` 对象——后代 inject 到的是同一个响应式引用，变化会同步。

---

### 5. v-model 和 .sync 的区别？

> Vue 3 中已移除 `.sync` 修饰符。原来的 `:title.sync="title"` 被 `v-model:title="title"` 取代。Vue 3 的 `v-model` 可以绑定多个，而 Vue 2 只能绑定一个。

---

## 十二、总结

```
数据向下 (props)，事件向上 (emits)
    → Vue 组件通信的核心原则

v-model = props + emits 的语法糖
    → 一个组件上可以绑多个 v-model

跨层级用 provide/inject
    → 提供 readonly 数据 + 修改方法

极少数需要访问子组件实例时，用 ref + defineExpose
    → 日常开发尽量少用，优先用 props/emits

状态共享复杂时，上 Pinia
    → 不要把 provide/inject 当全局状态管理用
```
