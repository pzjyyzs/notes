# Vue 3 编译优化原理

> 面试必问：Vue 3 为什么比 Vue 2 快？答案在编译器里。本文从静态提升到 Block Tree，把编译优化讲透。

---

## 一、Vue 的编译流程

模板不是直接运行在浏览器中的，而是被**编译成渲染函数**后再执行。

```
Template（开发者写的模板）
    │
    ▼ parse（解析）
  AST（抽象语法树）
    │
    ▼ transform（转换）
  JavaScript AST
    │
    ▼ generate（生成）
  render 函数（运行时代码）
```

为什么要编译？因为编译器可以在**编译时**分析模板，找出哪些东西永远不会变，提前做优化，减少运行时的开销。

---

## 二、三大编译优化

Vue 3 的编译优化可以归结为三件事：

```
1. 静态提升       → 不变的节点只创建一次
2. PatchFlags     → diff 时跳过不需要比较的属性
3. Block Tree     → diff 时跳过静态节点，只比较动态节点
```

---

## 三、静态提升（Static Hoisting）

### 3.1 问题

```vue
<template>
  <div>
    <h1>这是永远不会变的标题</h1>
    <p>{{ dynamicMessage }}</p>
  </div>
</template>
```

**Vue 2 的做法**：每次重新渲染，`<h1>` 和 `<p>` 的 VNode 都要重新创建。

**Vue 3 的做法**：编译器分析后发现 `<h1>` 整个是静态的，**把它提升到 render 函数外面，只创建一次，每次渲染直接复用**。

---

### 3.2 编译前后对比

```js
// ❌ Vue 2 生成的 render 函数（简化）
function render() {
  return h('div', [
    h('h1', '这是永远不会变的标题'),   // 每次渲染都创建新的 VNode
    h('p', ctx.dynamicMessage),        // 动态的，必须重新创建
  ])
}

// ✅ Vue 3 生成的 render 函数（简化）
const _hoisted_1 = h('h1', '这是永远不会变的标题')  // ← 提升到外面！

function render() {
  return h('div', [
    _hoisted_1,                        // 直接复用，不创建新的
    h('p', ctx.dynamicMessage),
  ])
}
```

**提升条件**：一个节点及它的所有子节点全是静态的（没有动态绑定、没有插值、没有指令）。

---

### 3.3 静态提升的效果

```
有提升：100 个静态节点 → 只在初始化时创建 1 次，以后复用
无提升：100 个静态节点 → 每次更新都创建 100 次（浪费）

在有大量静态内容（如文档页、博客页、帮助中心）中效果显著。
```

## 四、PatchFlags — 靶向更新

### 4.1 问题

Vue 2 的 diff 在比较两个 VNode 时，会对**所有属性**逐个比对：

```js
// Vue 2：逐个属性比
if (oldVNode.class !== newVNode.class) patchClass(el, newVNode.class)
if (oldVNode.style !== newVNode.style) patchStyle(el, newVNode.style)
if (oldVNode.props.id !== newVNode.props.id) patchProp(el, 'id', ...)
if (oldVNode.props.title !== newVNode.props.title) patchProp(el, 'title', ...)
if (oldVNode.children !== newVNode.children) patchChildren(...)
// ... 全部比一遍
```

但编译时我们已经知道这个节点**只有 class 是动态的**，其他都是静态的。为什么还要全部检查一遍？

---

### 4.2 PatchFlags 解决方案

编译器给每个动态节点打上一个**标记**，告诉运行时"这个节点只有这几样东西需要检查"。

```js
// PatchFlags 常量（在 @vue/shared 中定义）
const PatchFlags = {
  TEXT: 1,               // 动态文本内容
  CLASS: 2,              // 动态 class
  STYLE: 4,              // 动态 style
  PROPS: 8,              // 动态属性（class/style 以外的）
  FULL_PROPS: 16,        // 动态 key（需要完整 props diff）
  HYDRATE_EVENTS: 32,    // 事件监听
  STABLE_FRAGMENT: 64,   // 子元素顺序稳定的片段
  KEYED_FRAGMENT: 128,   // 带 key 的片段
  UNKEYED_FRAGMENT: 256, // 不带 key 的片段
  NEED_PATCH: 512,       // 需要非 prop 的 patch（如 ref）
  DYNAMIC_SLOTS: 1024,   // 动态插槽
  HOISTED: -1,           // 已静态提升
  BAIL: -2,              // diff 结束标志
}
```

---

### 4.3 实际例子

```vue
<template>
  <div :class="{ active: isActive }" id="container">
    <p>静态文字</p>
    <span>{{ message }}</span>
  </div>
</template>
```

Vue 3 编译器生成的 render 函数（简化）：

```js
function render(_ctx) {
  return h('div', {
    class: normalizeClass({ active: _ctx.isActive }),  // ← 只有这个是动态的
    id: 'container',                                     // ← 静态，不参与 diff
  }, [
    _hoisted_1,  // <p> 静态提升
    h('span', null, _ctx.message, 1 /* TEXT */),  // ← PatchFlag: 1，只比文本
  ])
}
```

运行时的 diff：

```js
// 伪代码：Vue 3 运行时的 patchElement
function patchElement(n1, n2) {
  const el = (n2.el = n1.el)
  const patchFlag = n2.patchFlag  // ← 拿到标记

  if (patchFlag & PatchFlags.CLASS) {
    // 只有标记了 CLASS 才比较 class
    patchClass(el, n2.class)
  }
  if (patchFlag & PatchFlags.STYLE) {
    // 只有标记了 STYLE 才比较 style
    patchStyle(el, n2.style)
  }
  if (patchFlag & PatchFlags.PROPS) {
    // 只有标记了 PROPS 才处理动态属性
    patchProps(el, n2.dynamicProps, n2.props)
  }
  // 没标记的 → 直接跳过！
}
```

**效果**：一个节点只更新它真正会变的那部分，不做无用检查。

---

### 4.4 组合标记

一个节点可能同时有多类动态内容：

```vue
<div :class="cls" :style="stl" @click="onClick">{{ text }}</div>
```

标记就是它们的**位或运算组合**：

```js
// CLASS(2) | STYLE(4) | PROPS(8) | TEXT(1) = 15
```

运行时用**位与运算**快速判断：

```js
if (patchFlag & PatchFlags.CLASS) { /* ... */ }  // true
if (patchFlag & PatchFlags.STYLE) { /* ... */ }  // true
if (patchFlag & PatchFlags.PROPS) { /* ... */ }  // true
if (patchFlag & PatchFlags.TEXT)  { /* ... */ }  // true
```

## 五、Block Tree — 靶向跳过

### 5.1 问题

```
<template>
  <div>
    <h1>静态标题</h1>
    <p>静态描述</p>
    <p>静态内容 A</p>
    <p>静态内容 B</p>
    <!-- ...50 个静态元素... -->
    <span>{{ dynamicMessage }}</span>
    <p>静态内容 C</p>
    <p>静态内容 D</p>
    <!-- ...50 个静态元素... -->
  </div>
</template>
```

即使有 PatchFlags，传统 diff 仍然需要**遍历整棵树**，检查每个节点。100 个静态节点 + 1 个动态节点 = 需要遍历 101 个节点。

Block Tree 的思路：**编译时把所有动态节点的引用收集起来，diff 时只遍历动态节点**。

---

### 5.2 什么是 Block

一个 Block（块）是一个特殊的 VNode，它额外存了一个 `dynamicChildren` 数组，记录了**直接子节点中所有动态的后代**。

```
<div>                     ← Block 节点
  ├── <h1>静态</h1>        ← 不在 dynamicChildren 中
  ├── <h2>静态</h2>        ← 不在
  ├── <span>{{ a }}</span> ← ✅ 在 dynamicChildren[0]
  ├── <p>静态</p>           ← 不在
  └── <span>{{ b }}</span> ← ✅ 在 dynamicChildren[1]
```

**diff 时**：

```js
// Vue 3 的 patchBlockChildren
function patchBlockChildren(n1, n2) {
  // 只遍历 dynamicChildren，不是遍历所有 children！
  for (let i = 0; i < n2.dynamicChildren.length; i++) {
    patchElement(n1.dynamicChildren[i], n2.dynamicChildren[i])
  }
  // 静态节点完全跳过！
}
```

---

### 5.3 怎么收集动态节点

在创建 VNode 时，有一个全局的 `currentDynamicChildren` 数组。创建动态 VNode 时会自动把自身 push 进去。

```js
// 伪代码：创建 VNode
function createVNode(type, props, children, patchFlag) {
  const vnode = { type, props, children, patchFlag, dynamicChildren: null }

  if (patchFlag !== undefined && currentDynamicChildren) {
    // 动态节点：把自己记录到父 Block 的 dynamicChildren 中
    currentDynamicChildren.push(vnode)
  }

  return vnode
}

// render 函数在执行时
function render() {
  return (openBlock(), createBlock('div', null, [
    _hoisted_1,                                    // 静态 → 不收集
    createVNode('span', null, ctx.msg, PatchFlags.TEXT),  // 动态 → 自动收集！
    _hoisted_2,                                    // 静态 → 不收集
  ]))
}

// openBlock() 创建了一个新的 dynamicChildren 数组
// createBlock() 把这个数组赋值给 div 这个 Block 节点
// 中间的动态 createVNode 都自动 push 到数组里
```

---

### 5.4 v-if / v-for 产生的 Block

```vue
<div>
  <section v-if="show">        ← 这是一个 Block（有 v-if）
    <span>{{ title }}</span>   ← 这是 section Block 的动态子节点
  </section>
</div>
```

`v-if` 和 `v-for` 指令会产生**新的 Block 节点**，形成 Block Tree：

```
div (Block)                    ← 根 Block
  └── section (Block)          ← v-if 产生的新 Block
        └── span (动态)        ← 只在 section 的 dynamicChildren 中
```

**Block Tree 的好处**：每个 Block 只关心自己的动态子节点，互不干扰。`v-if` 切换时只需要 patch 该 Block 内部的动态节点。

---

### 5.5 完整流程

```
传统 diff（Vue 2）：
  遍历整棵树 → 逐个节点 diff → 100个静态 + 1个动态 → 101 次检查

Block Tree diff（Vue 3）：
  找到根 Block → 直接访问 dynamicChildren → 只 diff 1 个动态节点
```

性能差距：**O(n) → O(d)**，其中 n = 全部节点数，d = 动态节点数。

## 六、v-once 和 v-memo 的编译优化

### 6.1 v-once

```vue
<div v-once>
  <h1>{{ title }}</h1>
  <p>{{ description }}</p>
</div>
```

编译后：整个子树被缓存。即使 `title` 和 `description` 变化，也不会重新渲染。

**编译结果**：

```js
// 初始渲染时缓存了 VNode 树
let _cache

function render() {
  return (_cache || (_cache = h('div', [
    h('h1', ctx.title),
    h('p', ctx.description),
  ])))
  // 之后 _cache 一直存在，永远不更新
}
```

**使用场景**：一次性渲染的内容（用户协议、帮助文档等）。

---

### 6.2 v-memo

```vue
<div v-memo="[items.length]">
  <p v-for="item in items" :key="item.id">{{ item.name }}</p>
</div>
```

编译后：只要 `items.length` 不变，这个子树就跳过 diff。

```js
function render() {
  return withMemo([ctx.items.length], () => {
    // memo 回调里的内容，只有依赖变化时才重新执行
    return h('div', ctx.items.map(item =>
      h('p', { key: item.id }, item.name)
    ))
  }, _cache, 0)
}
```

`v-memo` 比 `computed` 的缓存更"暴力"——它直接跳过整个子树的创建和 diff。

## 七、编译器对响应式的配合

### 7.1 把模板编译成最精准的更新代码

```vue
<template>
  <div>
    <p>{{ user.name }}</p>
  </div>
</template>
```

Vue 2 生成的代码：

```js
function render() {
  with (this) {
    // with 的作用域导致什么都可能变，无法优化
    return _c('div', [_c('p', [_v(_s(user.name))])])
  }
}
```

Vue 3 生成的代码：

```js
function render(_ctx) {
  return h('div', [
    h('p', _ctx.user.name, PatchFlags.TEXT /* 1 */)
    //                              ↑ 精确标记：只有文本
  ])
}
```

---

### 7.2 靶向更新的本质

```
模板编译时知道了：
  - 这个节点的什么属性是动态的 → PatchFlags
  - 哪些节点是完全静态的 → 静态提升
  - 哪些节点需要被追踪 → dynamicChildren

运行时：
  - 只更新有 PatchFlags 标记的属性
  - 静态节点直接复用 VNode
  - 只 diff dynamicChildren 里的节点

结果：Vue 的更新粒度精确到了「节点 + 属性」级别。
```

## 八、性能对比

```
场景：1000 个节点的表格，只有最后一列的数据会变化

Vue 2 的 diff：
  遍历 1000 个 tr → 每个 tr 遍历 5 个 td → 逐个比对
  → 约 5000 次 VNode 比较

Vue 3 的 diff：
  编译器收集了 1000 个动态 td 到 dynamicChildren
  → 只 diff 这 1000 个 td（且只比文本内容）
  → 跳过 4000 个静态 td
```

这在实际项目中差距非常大——**页面越复杂、静态内容越多，Vue 3 的优势越明显**。

## 九、编译器生成的代码示例

你可以用 [Vue SFC Playground](https://play.vuejs.org/) 直观看到编译结果。

```vue
<!-- 输入 -->
<script setup>
import { ref } from 'vue'
const msg = ref('hello')
const count = ref(0)
</script>

<template>
  <div id="app">
    <h1 class="title">Vue 3</h1>
    <p>{{ msg }}</p>
    <button @click="count++">clicked: {{ count }}</button>
  </div>
</template>
```

编译后的 render 函数（简化）：

```js
import { createElementVNode as _ceV, toDisplayString as _tds,
  openBlock as _ob, createElementBlock as _ceb } from 'vue'

const _hoisted_1 = { id: 'app' }
const _hoisted_2 = /*#__PURE__*/ _ceV('h1', { class: 'title' }, 'Vue 3', -1 /* HOISTED */)

export function render(_ctx, _cache) {
  return (_ob(), _ceb('div', _hoisted_1, [
    _hoisted_2,                                          // 静态提升，直接复用
    _ceV('p', null, _tds(_ctx.msg), 1 /* TEXT */),      // 只比文本
    _ceV('button', {
      onClick: _cache[0] || (_cache[0] = ($event) => (_ctx.count++))
    }, 'clicked: ' + _tds(_ctx.count), 1 /* TEXT */),   // 事件被缓存，只比文本
  ]))
}
```

逐行看：
- `_hoisted_1`：静态属性对象，提升
- `_hoisted_2`：静态 `<h1>`，整个 VNode 提升（PatchFlag `-1`）
- `1 /* TEXT */`：只有文本动态，只比文本内容
- `_cache[0]`：onClick 函数被缓存，避免每次创建新函数

## 十、面试题

### 1. Vue 3 比 Vue 2 快的三个核心原因？

> 1. **静态提升**：不变节点只创建一次，渲染时直接复用，不重新创建 VNode
> 2. **PatchFlags**：给动态节点打标记，diff 时只比较标记的属性，跳过的属性不做无用功
> 3. **Block Tree**：收集动态节点到 `dynamicChildren` 数组，diff 只遍历动态节点，跳过所有静态节点

---

### 2. PatchFlags 是怎么工作的？

> 编译器在编译模板时分析每个节点的绑定，给动态节点打上一个位标记（bit mask）。该标记精确说明了节点的**哪些部分**是动态的（TEXT、CLASS、STYLE、PROPS 等）。运行时 diff 通过**位与运算**快速判断哪些属性需要更新，其他一概跳过。

---

### 3. 静态提升和 v-once 的区别？

> **静态提升**是编译器自动做的优化，把完全不依赖任何响应式数据的节点提升到 render 函数外部。不需要开发者手动标记。
> **v-once** 是开发者手动标记的指令，即使节点包含动态内容（如 `{{ title }}`），也只渲染一次，之后不再更新。用于明确知道不会改变的动态内容。

---

### 4. Block Tree 和传统 diff 的区别？

> 传统 diff 遍历整棵 VNode 树，逐个节点比较（时间复杂度 O(n)，n = 总节点数）。
> Block Tree 在编译时把每个 Block 内的动态后代节点收集到 `dynamicChildren` 数组中，diff 时只遍历这个数组（时间复杂度 O(d)，d = 动态节点数）。
> 页面静态节点越多，Block Tree 的收益越大。

---

### 5. Vue 3 的更新粒度到了什么级别？

> **节点 + 属性级别**。PatchFlags 精确到"这个节点的哪个属性需要更新"。
> 一个 div 有 10 个属性，只有 `:class` 是动态的 → 只 patch class，其他 9 个属性不动。
> 对比 React：默认是整个组件重新渲染，需要 `React.memo` / `useMemo` 手动优化。

---

## 十一、总结

```
Vue 3 的编译优化三件套：

静态提升 ─────▶ 静态节点只创建一次，渲染直接复用
                 → 减少 VNode 创建

PatchFlags ───▶ 动态节点打标记，diff 时精确到属性
                 → 减少无用对比

Block Tree ───▶ 收集动态子节点，diff 跳过静态节点
                 → 减少遍历范围

组合效果：
  编译时分析 → 生成最优的 render 函数 → 运行时花最少的工作更新 DOM
```

> 🧠 **一句话**：Vue 3 把尽可能多的工作放在编译时完成，让运行时只需做最少的事。
