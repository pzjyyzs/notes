# Vue 3 生命周期钩子

> 理解生命周期，就是理解组件从诞生到消亡的完整过程。这是排查 bug、优化性能、理解框架行为的关键。

---

## 一、生命周期全景图

```
                    ┌─────────────────────┐
                    │    创建 Vue 应用     │
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │   setup() 执行      │ ← 组件初始化入口
                    │   组合式 API 初始化  │
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │  beforeCreate       │ ← 实例刚创建（Options API 用）
                    │  created            │ ← 实例创建完成
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │  编译模板 / 生成    │
                    │  render 函数        │
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                   ╱  beforeMount         ╲ ← DOM 挂载前
                  ╱                         ╲
                 │         首次渲染          │
                  ╲                         ╱
                   ╲  mounted             ╱ ← DOM 挂载完成 ✅
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                   ╱  beforeUpdate         ╲ ← 数据变化，重新渲染前
                  ╱                         ╲
                 │         重新渲染          │
                  ╲                         ╱
                   ╲  updated             ╱ ← 重新渲染完成
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                   ╱  beforeUnmount        ╲ ← 组件销毁前
                  ╱                         ╲     (清理定时器、取消订阅)
                 │                         │
                  ╲                         ╱
                   ╲  unmounted           ╱ ← 组件销毁完成 💀
                    └─────────────────────┘
```

## 二、钩子速查表

### 2.1 组合式 API vs Options API 对照

| 阶段 | Composition API | Options API | 说明 |
|------|------|------|------|
| 初始化 | `setup()` 本身 | `beforeCreate` → `created` | `setup()` 替代了这两个 |
| 挂载前 | `onBeforeMount` | `beforeMount` | 此时 DOM 还未生成 |
| 挂载完成 | `onMounted` | `mounted` | ✅ 可以访问 DOM |
| 更新前 | `onBeforeUpdate` | `beforeUpdate` | 虚拟 DOM 已变，真实 DOM 未变 |
| 更新完成 | `onUpdated` | `updated` | 真实 DOM 已更新 |
| 卸载前 | `onBeforeUnmount` | `beforeUnmount` | ⚠️ 清理副作用的最佳时机 |
| 卸载完成 | `onUnmounted` | `unmounted` | 组件实例完全销毁 |
| 错误捕获 | `onErrorCaptured` | `errorCaptured` | 捕获子孙组件错误 |
| 激活 | `onActivated` | `activated` | `<KeepAlive>` 缓存后重新激活 |
| 停用 | `onDeactivated` | `deactivated` | `<KeepAlive>` 缓存组件时停用 |
| Dev 调试 | `onRenderTracked` | `renderTracked` | 调试用：追踪到响应式依赖 |
| Dev 调试 | `onRenderTriggered` | `renderTriggered` | 调试用：渲染被哪个依赖触发 |

---

### 2.2 基本使用

```vue
<script setup>
import {
  onBeforeMount,
  onMounted,
  onBeforeUpdate,
  onUpdated,
  onBeforeUnmount,
  onUnmounted,
} from 'vue'

onBeforeMount(() => {
  console.log('1. beforeMount — DOM 还没生成')
})

onMounted(() => {
  console.log('2. mounted — DOM 已生成，可以操作了')
})

onBeforeUpdate(() => {
  console.log('3. beforeUpdate — 数据变了，DOM 还没更新')
})

onUpdated(() => {
  console.log('4. updated — DOM 已更新完成')
})

onBeforeUnmount(() => {
  console.log('5. beforeUnmount — 即将销毁，清理副作用')
})

onUnmounted(() => {
  console.log('6. unmounted — 组件已完全销毁')
})
</script>
```

## 三、各阶段详解

### 3.1 setup() — 组件初始化

```vue
<script setup>
// <script setup> 本质就是 setup() 函数的语法糖
// 这里是组件最早执行的地方

import { ref } from 'vue'

const count = ref(0)
// 此时：
// ✅ 可以声明响应式数据
// ✅ 可以定义方法
// ❌ 不能访问 DOM（还没渲染）
// ❌ 不能访问 this（undefined）
</script>
```

**setup() 替代了 Vue 2 的 `beforeCreate` 和 `created`**：

| Vue 2 Options API | Vue 3 Composition API |
|------|------|
| `beforeCreate()` | `setup()` 开头 |
| `created()` | `setup()` 末尾 |

---

### 3.2 onBeforeMount — 挂载前

```vue
<script setup>
import { ref, onBeforeMount } from 'vue'

const el = ref(null)

onBeforeMount(() => {
  console.log(el.value) // null — DOM 还没生成
  // 此时做不了任何 DOM 操作
  // 主要用于服务端渲染（SSR）场景
})
</script>
```

**执行时机**：虚拟 DOM 编译完成，但还没有挂载到真实 DOM。

**能做**：几乎不需要做什么。SSR 中做一些服务端特有的逻辑。

---

### 3.3 onMounted — 挂载完成（最常用）

```vue
<script setup>
import { ref, onMounted } from 'vue'

const el = ref(null)

onMounted(() => {
  // ✅ 此时 DOM 已存在
  console.log(el.value)           // <div>...</div>
  console.log(el.value.offsetHeight) // 可以获取尺寸

  // 常见场景：
  // - 发起 API 请求获取初始数据
  // - 初始化第三方库（图表、地图）
  // - 添加全局事件监听
  // - 自动聚焦输入框
  el.value.focus?.()
})
</script>

<template>
  <div ref="el">内容</div>
</template>
```

**注意**：`onMounted` 不保证所有子组件也已挂载完成。如果需要在**整个视图渲染完成后**做操作，使用 `nextTick`：

```js
import { nextTick, onMounted } from 'vue'

onMounted(async () => {
  await nextTick()
  // 现在整个视图（包括子组件）都完成了
})
```

---

### 3.4 onBeforeUpdate — 更新前

```vue
<script setup>
import { ref, onBeforeUpdate } from 'vue'

const count = ref(0)
const el = ref(null)

onBeforeUpdate(() => {
  // 此时：数据已变，虚拟 DOM 已更新，但真实 DOM 还是旧的
  console.log('数据值：', count.value)        // 新值
  console.log('DOM 内容：', el.value?.textContent) // 旧值！
})
</script>
```

**使用场景极少**。主要在调试时了解数据变化来源。

---

### 3.5 onUpdated — 更新完成

```vue
<script setup>
import { ref, onUpdated, nextTick } from 'vue'

const count = ref(0)
const listRef = ref(null)

onUpdated(() => {
  // DOM 已更新完成
  console.log('新 DOM：', listRef.value?.children.length)

  // ⚠️ 但子组件可能还没更新完成
  // 如果需要确保整个子树更新完成：
  await nextTick()
})
</script>
```

**注意**：
- `onUpdated` 会在**组件任何 DOM 更新后**调用
- 如果在此钩子中**修改响应式数据**，可能导致无限循环
- 如果需要的话，加个守卫条件

```js
onUpdated(() => {
  // ❌ 危险：可能导致无限循环
  // count.value++

  // ✅ 加条件守卫
  if (someCondition) {
    count.value++
  }
})
```

---

### 3.6 onBeforeUnmount — 卸载前（重要！）

```vue
<script setup>
import { onBeforeUnmount } from 'vue'

let timer = null
let resizeHandler = null

onBeforeUnmount(() => {
  // ⚠️ 这里是最佳清理时机：
  // 1. 清除定时器
  clearInterval(timer)
  clearTimeout(timer)

  // 2. 移除事件监听
  window.removeEventListener('resize', resizeHandler)

  // 3. 取消网络请求
  controller.abort()

  // 4. 取消订阅
  subscription.unsubscribe()

  // 5. 销毁第三方实例
  chart.destroy()
})
</script>
```

> **不清理会怎样？** 定时器照常运行（内存泄漏），事件监听照常触发（但组件不存在了，可能报错）。

---

### 3.7 onUnmounted — 卸载完成

```js
onUnmounted(() => {
  console.log('组件已完全销毁，所有指令和事件已解绑')
  // 通常 onBeforeUnmount 就足够了
  // 这里做日志、统计上报等
})
```

## 四、KeepAlive 专属钩子

### 4.1 onActivated / onDeactivated

```vue
<script setup>
import { onActivated, onDeactivated } from 'vue'

// 组件被 <KeepAlive> 包裹时生效

onActivated(() => {
  console.log('组件从缓存中恢复，重新激活')
  // 刷新数据、重新获取焦点等
})

onDeactivated(() => {
  console.log('组件被缓存，暂时停用')
  // 暂停轮询、保存草稿等
})
</script>
```

---

### 4.2 KeepAlive 的生命周期流程

```
普通组件：
  创建 → mounted → updated → unmounted → 💀 (重新用要重新创建)

KeepAlive 组件：
  创建 → mounted → deactivated (缓存)
                      │
            ┌─────────▼───────────┐
            │ 组件回到前台          │
            │ 不需要重新创建！      │
            └─────────┬───────────┘
                      │
             activated (恢复)
                      │
            deactivated (再次缓存)
                      │
                    ...(可以反复)
                      │
                unmounted (最终销毁)
```

## 五、父子组件生命周期执行顺序

### 5.1 挂载阶段

```
父 setup()           ─┐
父 onBeforeMount      ├── 父组件初始化
子 setup()            │
子 onBeforeMount      │
子 onMounted          │    ← 子组件先挂载完成
父 onMounted          ─┘    ← 父组件最后挂载完成
```

> ⚡ **子组件的 `mounted` 先于父组件的 `mounted`**

---

### 5.2 更新阶段

```
父 onBeforeUpdate     ─┐
子 onBeforeUpdate      │
子 onUpdated           │    ← 子先更新完成
父 onUpdated           ─┘    ← 父后更新完成
```

---

### 5.3 卸载阶段

```
父 onBeforeUnmount    ─┐
子 onBeforeUnmount     │
子 onUnmounted         │    ← 子先卸载
父 onUnmounted         ─┘    ← 父后卸载
```

---

### 5.4 一句话记忆

> **挂载：子先完，父后完；卸载：子先卸，父后卸。**

## 六、调试钩子（仅开发模式）

### 6.1 onRenderTracked — 追踪依赖

```vue
<script setup>
import { ref, onRenderTracked } from 'vue'

const count = ref(0)

onRenderTracked((event) => {
  console.log('渲染时追踪到的依赖：', event)
  // event.deps — 本次渲染追踪到的所有依赖
  // event.key — 被访问的属性名
  // event.target — 被访问的对象
})
</script>
```

每次重新渲染时触发，告诉你这次渲染追踪了哪些响应式数据。

---

### 6.2 onRenderTriggered — 触发来源

```vue
<script setup>
import { ref, onRenderTriggered } from 'vue'

const count = ref(0)

onRenderTriggered((event) => {
  console.log('触发本次渲染的原因：', event)
  // event.key — 哪个属性变了
  // event.oldValue / event.newValue — 新旧值
})
</script>
```

与 `onRenderTracked` 的区别：
| | onRenderTracked | onRenderTriggered |
|------|------|------|
| 触发时机 | 每次渲染 | 响应式数据变化导致重新渲染时 |
| 初始渲染 | ✅ 触发 | ❌ 不触发（初始没有"变化"） |
| 用途 | 看依赖了谁 | 看谁触发了更新 |

## 七、实战场景

### 7.1 获取 Dom 元素

```vue
<script setup>
import { ref, onMounted } from 'vue'

const canvasRef = ref(null)

onMounted(() => {
  const ctx = canvasRef.value.getContext('2d')
  ctx.fillStyle = 'red'
  ctx.fillRect(0, 0, 100, 100)
})
</script>

<template>
  <canvas ref="canvasRef" width="400" height="300"></canvas>
</template>
```

---

### 7.2 滚动事件监听

```vue
<script setup>
import { ref, onMounted, onBeforeUnmount } from 'vue'

const scrollY = ref(0)

function handleScroll() {
  scrollY.value = window.scrollY
}

onMounted(() => {
  window.addEventListener('scroll', handleScroll)
})

onBeforeUnmount(() => {
  // ✅ 必须清理！否则组件销毁后事件监听还在
  window.removeEventListener('scroll', handleScroll)
})
</script>
```

---

### 7.3 轮询数据

```vue
<script setup>
import { ref, onMounted, onBeforeUnmount, onActivated, onDeactivated } from 'vue'

const data = ref(null)
let timer = null

function startPolling() {
  timer = setInterval(async () => {
    data.value = await fetchData()
  }, 5000)
}

function stopPolling() {
  clearInterval(timer)
  timer = null
}

onMounted(() => {
  fetchData().then(res => data.value = res) // 立即获取一次
  startPolling()                             // 然后轮询
})

onBeforeUnmount(() => {
  stopPolling()  // ✅ 清理定时器，防止内存泄漏
})

// 如果组件在 KeepAlive 中：
onActivated(() => startPolling())   // 激活时恢复轮询
onDeactivated(() => stopPolling())  // 缓存时暂停轮询
</script>
```

---

### 7.4 第三方库初始化

```vue
<script setup>
import { ref, onMounted, onBeforeUnmount, watch } from 'vue'
import Chart from 'chart.js/auto'

const chartRef = ref(null)
const chartData = ref({ labels: [], values: [] })
let chartInstance = null

onMounted(() => {
  chartInstance = new Chart(chartRef.value, {
    type: 'bar',
    data: { /* ... */ }
  })
})

// 数据变化时更新图表
watch(chartData, (newData) => {
  if (chartInstance) {
    chartInstance.data.labels = newData.labels
    chartInstance.data.datasets[0].data = newData.values
    chartInstance.update()
  }
}, { deep: true })

onBeforeUnmount(() => {
  chartInstance?.destroy()  // ✅ 销毁图表实例
})
</script>

<template>
  <canvas ref="chartRef"></canvas>
</template>
```

## 八、生命周期与异步

### 8.1 生命周期钩子可以写 async 吗？

```vue
<script setup>
import { onMounted } from 'vue'

// ✅ 可以写 async，但需要注意
onMounted(async () => {
  const data = await fetch('/api/data')
  // 这里执行时，其他同步的 onMounted 可能已经执行完了
  // Vue 不会等待 async onMounted 完成
})
</script>
```

> ⚠️ **Vue 不会等待 async 生命周期钩子**。也就是说，父组件的 `onMounted` 中的 `await` 不会阻止子组件挂载。

---

### 8.2 Suspense 与生命周期

```vue
<script setup>
// 当组件被 <Suspense> 包裹且有 async setup 时：

const data = await fetch('/api/data')  // 顶层 await
// 组件会等到 await 完成后才进入 onMounted
// 在此之前 Suspense 显示 fallback 内容
</script>
```

使用 `Suspense` 时，`async setup` 完成后才会触发 `onMounted`。

## 九、面试题

### 1. Vue 3 的生命周期有哪些？

> 组合式 API 共 8 个常用钩子：
> `onBeforeMount` → `onMounted` → `onBeforeUpdate` → `onUpdated` → `onBeforeUnmount` → `onUnmounted` + KeepAlive 专属的 `onActivated` / `onDeactivated`
>
> Options API 多了 `beforeCreate` 和 `created`，但在 Composition API 中被 `setup()` 替代。

---

### 2. created 和 mounted 的区别？

> `created`：实例创建完，但 DOM 未生成，不能操作 DOM
> `mounted`：DOM 已挂载，可以访问和操作 DOM
>
> 在 Vue 3 Composition API 中，`setup()` 替代了 `created`，`onMounted` 替代了 `mounted`。

---

### 3. 父子组件的生命周期执行顺序？

> **挂载**：父 setup → 父 beforeMount → 子 setup → 子 beforeMount → 子 mounted → 父 mounted
>
> **更新**：父 beforeUpdate → 子 beforeUpdate → 子 updated → 父 updated
>
> **卸载**：父 beforeUnmount → 子 beforeUnmount → 子 unmounted → 父 unmounted

---

### 4. ajax 请求放在 created 还是 mounted？

> **`onMounted`（等价于 mounted）更合适**：
> - `created/setup` 阶段 DOM 还不存在，如果请求完成后需要操作 DOM 还得等
> - 放在 `onMounted` 可以请求和 DOM 操作一起处理
> - SSR 场景：`created/setup` 在服务端也会执行，可能导致重复请求
> - 实际上对于用户体验来说，created 和 mounted 的时间差极小（几 ms），更推荐 `onMounted`

---

### 5. 为什么要在 onBeforeUnmount 中清理副作用？

> 组件销毁后，如果不清除：
> 1. **定时器/requestAnimationFrame** 继续运行 → 更新已销毁组件的状态 → 控制台警告 + 内存泄漏
> 2. **事件监听**继续触发 → 尝试访问不存在的 DOM → 报错
> 3. **WebSocket/SSE 连接**不关闭 → 浪费网络资源
> 4. **第三方实例**不销毁 → 占用内存

---

## 十、总结

```
setup()                → 初始化，声明响应式数据（替代 beforeCreate + created）

onMounted              → 最常用：操作 DOM、发请求、初始化第三方库
                          
onBeforeUpdate/onUpdated → 极少直接用，调试或极端场景

onBeforeUnmount        → 清理！定时器、事件监听、订阅、第三方实例
                          
onUnmounted            → 清理的收尾，日志/统计

onActivated/onDeactivated → KeepAlive 专用，切换轮询/强求状态
```

> 🧠 **记忆口诀**：
> setup 初始化，mounted 操作 DOM，unmount 清垃圾，KeepAlive 用 activate。
> 子先父后挂载完，子先父后卸载完。
